# Ollama для Windows — установка как служба

Комплект скриптов для развёртывания [Ollama](https://ollama.com) на Windows в виде службы через [NSSM](https://nssm.cc), с сетевым доступом, ротацией логов, политикой автоперезапуска и опциональной автозагрузкой моделей. Оптимизирован под **NVIDIA RTX 4060 (8 ГБ VRAM)**, но работает на любом железе с подстройкой INI.

---

## Состав комплекта

| Файл | Назначение |
|---|---|
| `ollama-windows-amd64.ini` | Единый конфиг: пути, сеть, служба, URL, модели, производительность |
| `ollama-windows-amd64.ps1` | Установка: скачивание, регистрация службы, брандмауэр, PATH, health-check, модели |
| `ollama-windows-uninstall.ps1` | Удаление: остановка службы, очистка PATH/брандмауэра/переменных, опциональное удаление каталогов |
| `README.md` | Этот файл |

Все три скрипта должны лежать **в одной папке** — INI по умолчанию ищется рядом со скриптом. Кэш архивов (опция `KeepDownloads=true`) тоже сохраняется в папку скрипта, если не указано иное.

---

## Требования

| Компонент | Требование |
|---|---|
| ОС | Windows 10/11 Pro/Enterprise или Windows Server 2019/2022/2025 |
| Права | Локальный администратор (скрипт сам запросит UAC) |
| GPU | NVIDIA, драйвер **550 или новее** (для CUDA-совместимости) |
| PowerShell | 5.1 или 7.x |
| Диск | Достаточно места под модели (7–8B в Q4_K_M ≈ 4.5–5 ГБ каждая) |

Официальная документация Ollama: <https://github.com/ollama/ollama/blob/main/docs/faq.md>

## Быстрый старт

```powershell
# 1. Скопировать три файла в папку, например D:\AI\Deploy
# 2. Отредактировать ollama-windows-amd64.ini (минимум: FirewallSubnet, OllamaUrl)
cd D:\AI\Deploy
.\ollama-windows-amd64.ps1
```

Скрипт:
1. Запросит UAC.
2. Остановит существующую службу Ollama (если была).
3. Проверит порт `11434`.
4. Создаст каталоги и выдаст `SYSTEM` права на профиль и модели.
5. Скачает NSSM и Ollama (с кэшированием — см. `[downloads]`).
6. Настроит Machine-переменные `OLLAMA_HOST`, `OLLAMA_MODELS` и добавит `OllamaDir` в `PATH`.
7. Создаст правило брандмауэра для указанной подсети.
8. Зарегистрирует службу через NSSM со всеми параметрами `[performance]`, ротацией логов и автоперезапуском.
9. Запустит службу и выполнит health-check (до 15 попыток по 2 с).
10. Покажет интерактивное меню выбора моделей (если `DownloadModels=true`) и скачает выбранные.

## Конфигурация `ollama-windows-amd64.ini`

INI-файл состоит из восьми секций. Все параметры опциональны — при отсутствии используются значения по умолчанию. Булевы значения принимают `true/false`, `1/0`, `yes/no`, `on/off`.

### Секция `[paths]` — каталоги

| Ключ | По умолчанию | Описание |
|---|---|---|
| `OllamaDir` | `D:\AI\Ollama` | Каталог для бинарников Ollama. Также добавляется в `PATH` при `AddToPath=true`. |
| `ModelsDir` | `D:\AI\Models` | Каталог для скачанных моделей (`OLLAMA_MODELS`). Может быть большим — при `-PurgeModels` удаляется. |
| `NssmDir` | `C:\Program Files\NSSM` | Куда распаковать NSSM. Требуются права администратора. |
| `LogsDir` | `<OllamaDir>\logs` | Логи NSSM (`ollama.out.log`, `ollama.err.log`). Ротация по 10 МБ. |

### Секция `[ollama]` — профиль

| Ключ | По умолчанию | Описание |
|---|---|---|
| `OllamaHome` | `OllamaDir` | Домашний каталог профиля Ollama. Внутри создаётся `.ollama` с ключом `id_ed25519`. Служба получает его через `USERPROFILE` / `HOME`. |

> **Зачем отдельный профиль.** По умолчанию служба под `LocalSystem` писала бы ключ в `C:\Windows\System32\config\systemprofile\.ollama`. Скрипт явно задаёт `USERPROFILE=OllamaHome`, чтобы профиль был в управляемом месте. Если старая папка `systemprofile\.ollama` существует, ключ из неё копируется в новый профиль.

### Секция `[service]` — служба Windows

| Ключ | По умолчанию | Описание |
|---|---|---|
| `ServiceName` | `Ollama` | Имя службы для `sc.exe`, `Get-Service` и NSSM. |
| `StartType` | `SERVICE_DELAYED_AUTO_START` | `SERVICE_AUTO_START`, `SERVICE_DELAYED_AUTO_START` или `SERVICE_DEMAND_START`. Для GPU-хоста рекомендуется `DELAYED` — драйвер CUDA успевает инициализироваться. |
| `StartTimeoutSeconds` | `45` | Таймаут `WaitForStatus('Running')` после запуска службы. |
| `AppRestartDelay` | `10000` | Задержка перед автоперезапуском после падения, мс. |
| `AddToPath` | `true` | Добавить `OllamaDir` в Machine `PATH` (без дубликатов). Даёт возможность вызывать `ollama` из любой консоли. |

### Секция `[network]` — сеть и брандмауэр

| Ключ | По умолчанию | Описание |
|---|---|---|
| `Host` | `0.0.0.0` | `0.0.0.0` — доступ по сети; `127.0.0.1` — только локально. |
| `Port` | `11434` | TCP-порт API. |
| `FirewallEnabled` | `true` | Создавать ли правило входящего трафика. |
| `FirewallSubnet` | *(пусто)* | Подсеть, которой разрешён доступ (например, `192.168.1.0/24`). Пусто → правило не создаётся. |
| `Origins` | *(пусто)* | CORS для веб-клиентов (Open WebUI, кастомные панели). Формат: `http://localhost:3000,https://myapp.com`. Пусто → `OLLAMA_ORIGINS` не задаётся. |

> ⚠️ **Безопасность.** Ollama **не имеет встроенной аутентификации**. При `Host=0.0.0.0` любой, кто может достучаться до порта, способен делать inference, **скачивать и удалять модели**. Всегда ограничивайте `FirewallSubnet`. Для недоверенных сетей ставьте перед Ollama reverse proxy с TLS и Basic Auth (Caddy, Nginx).

### Секция `[downloads]` — скачивание дистрибутивов

| Ключ | По умолчанию | Описание |
|---|---|---|
| `NssmUrl` | `https://github.com/dkxce/NSSM/.../NSSM_v2.25.zip` | URL архива NSSM. Можно заменить на официальный `https://nssm.cc/download` (архив `nssm-2.24.zip`). |
| `OllamaUrl` | `https://github.com/ollama/ollama/releases/download/v0.40.1/ollama-windows-amd64.zip` | URL архива Ollama. **Всегда проверяйте тег** на <https://github.com/ollama/ollama/releases>. Несуществующий тег → 404 на этапе скачивания. |
| `DownloadCacheDir` | *(пусто → папка скрипта)* | Куда сохранять скачанные архивы. Относительный путь (например, `dist`) разрешается относительно папки скрипта; абсолютный — как есть. |
| `KeepDownloads` | `true` | `true` — сохранять архивы и переиспользовать при повторных запусках; `false` — скачивать в `%TEMP%` и удалять после распаковки. |

**Как работает кэш.** Рядом с каждым архивом создаётся файл-стамп `<archive>.url` с URL, с которого он скачан. При следующем запуске:
- если URL в INI совпадает со стампом — архив переиспользуется;
- если URL изменился (например, вы обновили тег Ollama) — архив перекачивается автоматически;
- `-ForceDownload` принудительно перекачивает архивы независимо от стампа.

### Секция `[models]` — автозагрузка моделей

| Ключ | По умолчанию | Описание |
|---|---|---|
| `DownloadModels` | `true` | Скачивать ли модели после успешной установки и health-check. |
| `Interactive` | `true` | Показывать интерактивное меню выбора. Если `false` или запуск с `-Force` — качаем ровно то, что в `Models`. |
| `Models` | *(пусто)* | Список моделей через запятую для неинтерактивного режима. В интерактивном режиме они предвыбраны в меню. |

**Интерактивное меню** предлагает рекомендованные для 8 ГБ VRAM модели:

| № | Модель | Назначение | Размер (Q4_K_M) |
|---|---|---|---|
| 1 | `llama3.1:8b` | Общий чат | ≈ 4.9 ГБ |
| 2 | `qwen2.5:7b` | Баланс качества | ≈ 4.7 ГБ |
| 3 | `qwen2.5-coder:7b` | Кодинг | ≈ 4.7 ГБ |
| 4 | `deepseek-r1:8b` | Reasoning | ≈ 4.9 ГБ |
| 5 | `gemma2:2b` | Лёгкая, много контекста | ≈ 1.6 ГБ |
| 6 | `qwen2.5:3b` | Быстрая | ≈ 2 ГБ |

Ввод в меню:
- `1,3` — скачать модели №1 и №3;
- `a` — скачать все;
- `n` — пропустить;
- Enter — оставить предвыбранные из INI.

**Уже установленные модели пропускаются** — проверка через `ollama list`. Скрипт можно перезапускать сколько угодно раз без лишнего трафика.

### Секция `[performance]` — параметры Ollama

| Ключ | По умолчанию | Переменная Ollama | Описание |
|---|---|---|---|
| `KeepAlive` | `10m` | `OLLAMA_KEEP_ALIVE` | Время удержания модели в памяти после последнего запроса (`5m`, `24h`, `-1` — постоянно). Для 8 ГБ: `10m` — разумно; `24h` — если сервер фоновый. |
| `FlashAttention` | `1` | `OLLAMA_FLASH_ATTENTION` | **Обязателен** при квантованном KV-кэше. Без него `q8_0`/`q4_0` не активируется. Скрипт принудительно включает FA, если `KvCacheType != f16`, и предупреждает. |
| `KvCacheType` | `q8_0` | `OLLAMA_KV_CACHE_TYPE` | `f16` (макс. точность, больше VRAM), `q8_0` (≈ −50% VRAM, минимальная потеря), `q4_0` (макс. экономия, потеря качества заметнее). |
| `NumParallel` | `1` | `OLLAMA_NUM_PARALLEL` | Количество одновременных слотов. Каждый слот умножает KV-кэш. Для одного пользователя — `1`. |
| `MaxLoadedModels` | `1` | `OLLAMA_MAX_LOADED_MODELS` | Максимум моделей в VRAM. **`1` критично для 8 ГБ** — предотвращает OOM при переключении. |
| `Debug` | `0` | `OLLAMA_DEBUG` | `1` — включить отладочные логи Ollama (полезно для диагностики CUDA). |

> **Валидация.** Если задан `KvCacheType=q8_0` (или `q4_0`) и `FlashAttention=0`, скрипт автоматически поднимает FA до `1` и печатает предупреждение — чтобы не получить «тихо не работающую» настройку.

## Параметры запуска

### `ollama-windows-amd64.ps1` (установка)

| Параметр | Тип | Описание |
|---|---|---|
| `-ConfigPath <string>` | опционально | Путь к INI. По умолчанию — `ollama-windows-amd64.ini` рядом со скриптом. |
| `-Force` | switch | Не задавать интерактивных вопросов (в том числе не показывать меню моделей — качать ровно то, что в `[models] Models`). |
| `-ForceDownload` | switch | Принудительно перекачать NSSM и Ollama, даже если кэш есть. Полезно при обновлении версии в INI. |
| `-NoPause` | switch | Не ждать Enter в конце (для Планировщика/CI). |

**Примеры:**

```powershell
# Обычная установка с меню моделей
.\ollama-windows-amd64.ps1

# Неинтерактивная установка (для CI)
.\ollama-windows-amd64.ps1 -Force -NoPause

# Обновление версии Ollama (после правки OllamaUrl в INI)
.\ollama-windows-amd64.ps1 -ForceDownload -Force -NoPause

# Нестандартный INI
.\ollama-windows-amd64.ps1 -ConfigPath D:\configs\ollama.ini
```

### `ollama-windows-uninstall.ps1` (удаление)

| Параметр | Тип | Описание |
|---|---|---|
| `-ConfigPath <string>` | опционально | Путь к INI. По умолчанию — рядом со скриптом. |
| `-PurgeProfile` | switch | Удалить `<OllamaHome>\.ollama` (включая `id_ed25519`!). |
| `-PurgeModels` | switch | Удалить `<ModelsDir>`. Может быть много гигабайт. |
| `-PurgeOllama` | switch | Удалить `<OllamaDir>` с бинарниками. Если внутри лежит `.ollama` и не задан `-PurgeProfile` — пропускается. |
| `-PurgeLogs` | switch | Удалить `<LogsDir>`. |
| `-Force` | switch | Не задавать интерактивных подтверждений для деструктивных операций. |
| `-NoPause` | switch | Не ждать Enter в конце. |

**Примеры:**

```powershell
# Удалить службу, сохранив всё остальное
.\ollama-windows-uninstall.ps1

# Полная очистка
.\ollama-windows-uninstall.ps1 -PurgeProfile -PurgeModels -PurgeOllama -PurgeLogs -Force -NoPause
```

**Что делается всегда:**
- Останавливает и удаляет службу.
- Удаляет правило брандмауэра по маске `"Ollama API*"` (сиротские правила от старых подсетей тоже убираются).
- Убирает `OllamaDir` из Machine `PATH` (только если `AddToPath=true`).
- Сбрасывает Machine `OLLAMA_HOST` и `OLLAMA_MODELS`.

**Что не удаляется по умолчанию:** NSSM (`NssmDir`), сам INI, архивы в кэше (`DownloadCacheDir`), каталоги профиля/моделей/бинарников/логов — только по явным флагам `-Purge*`.

## Типичные сценарии

### Обновление версии Ollama

1. Отредактировать `OllamaUrl` в INI (например, `v0.40.1` → `v0.41.0`).
2. Запустить: `.\ollama-windows-amd64.ps1 -ForceDownload`.

Скрипт перекачает оба архива и переустановит бинарники. Профиль и модели не затрагиваются — они лежат отдельно (`ModelsDir`, `OllamaHome\.ollama`).

### Смена порта или подсети

1. Отредактировать `[network] Port` или `FirewallSubnet` в INI.
2. Запустить: `.\ollama-windows-amd64.ps1 -Force -NoPause`.

Служба пересоздаётся, старое правило брандмауэра удаляется, новое — создаётся.

### Использование веб-интерфейса (Open WebUI, LibreChat и др.)

Заполните `Origins`:

```ini
[network]
Origins=http://localhost:3000,http://192.168.1.50:8080
```

Без этого веб-клиенты получат `403 Forbidden` на CORS-запросы.

### Добавление моделей после установки

```powershell
ollama pull llama3.1:70b
```

Благодаря `AddToPath=true` команда работает из любой консоли. Либо через API:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:11434/api/pull -Body '{"name":"llama3.1:70b"}' -ContentType application/json
```

## Проверка работы

```powershell
# Статус службы
Get-Service Ollama

# API локально
Invoke-RestMethod http://127.0.0.1:11434/api/tags

# API из разрешённой подсети
Invoke-RestMethod http://<IP-сервера>:11434/api/tags

# Какие модели в памяти и где (GPU/CPU)
ollama ps

# Список скачанных моделей
ollama list

# Запуск модели в интерактивном режиме
ollama run llama3.1:8b
```

Логи: `<LogsDir>\ollama.out.log` и `ollama.err.log`, ротация по 10 МБ.

## Подбор моделей под RTX 4060 8 ГБ

При контексте 8K и `KvCacheType=q8_0` в 8 ГБ VRAM чисто (без выгрузки на CPU) работают модели класса 7–8B в Q4_K_M:

| Задача | Модель | Размер |
|---|---|---|
| Общий чат | `llama3.1:8b` | ≈ 4.9 ГБ |
| Баланс | `qwen2.5:7b` | ≈ 4.7 ГБ |
| Кодинг | `qwen2.5-coder:7b` | ≈ 4.7 ГБ |
| Reasoning | `deepseek-r1:8b` | ≈ 4.9 ГБ |
| Лёгкая | `gemma2:2b` / `qwen2.5:3b` | 1.6–2 ГБ |

**Проверка:** после загрузки модели выполните `ollama ps`. `100% GPU` — отлично. `xx%/yy% CPU/GPU` — модель не поместилась, скорость упадёт в разы. В этом случае:
- возьмите модель меньшего размера (7B вместо 8B);
- используйте Q4_K_M вместо Q5/Q6;
- поставьте `KvCacheType=q4_0` вместо `q8_0`;
- уменьшите контекст (`ollama run --num-ctx 4096`).

## Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `404` при скачивании Ollama | Несуществующий тег в `OllamaUrl` | Проверьте тег на <https://github.com/ollama/ollama/releases>. |
| Служба `Running`, API не отвечает | Ollama не успел поднять роутер или CUDA падает под `LocalSystem` | Проверьте `ollama.err.log`. Health-check в скрипте ждёт до 30 с. Если в логах ошибки CUDA — проверьте драйвер и права `SYSTEM`. |
| `ollama` не находится в консоли | Текущая консоль держит старый `PATH` | Откройте новую консоль. Проверьте `$env:Path -split ';' | Select-String Ollama`. |
| `ollama ps` → `xx%/yy% CPU/GPU` | Модель не помещается в VRAM | См. «Подбор моделей». |
| Веб-клиент получает `403` | Не задан `OLLAMA_ORIGINS` | Добавьте origin клиента в `[network] Origins`, переустановите. |
| Порт `11434` занят после установки | Другой процесс (не Ollama) слушает порт | `Get-NetTCPConnection -LocalPort 11434 -State Listen` покажет `OwningProcess` (PID). |
| Служба удалена, но `ollama.exe` не удалился | `-PurgeOllama` не задан | `.\ollama-windows-uninstall.ps1 -PurgeOllama`. |
| Логи растут слишком быстро | `OLLAMA_DEBUG=1` или аномальная нагрузка | Ротация 10 МБ уже включена; проверьте `[performance] Debug=0`. |
| `Нет доступа к .ollama` при миграции | ACL на старом профиле | Скрипт выдаёт `SYSTEM:F` на новый профиль; старый копируется с `-ErrorAction SilentlyContinue`. При ошибках скопируйте вручную. |

## Безопасность

- **Ограничивайте `FirewallSubnet`.** Правило брандмауэра создаётся только для указанной подсети, но если оставить пусто — правило не создаётся вообще.
- **Ollama не имеет аутентификации.** Не выставляйте `Host=0.0.0.0` в публичную сеть. Для недоверенных сегментов — reverse proxy (Caddy, Nginx) с TLS и Basic Auth / API-key.
- **`-PurgeProfile` удаляет `id_ed25519`.** Это ключ, которым Ollama подписывает запросы к реестру моделей. Без него — пересоздастся автоматически, но если вы привязывали его к чему-то ещё, сохраните.
- **Не удаляйте `C:\Windows\System32\config\systemprofile\.ollama` сразу после миграции.** Убедитесь, что новый профиль в `OllamaHome\.ollama` работает и ключ на месте.

## Отладка скрипта

Полезные команды при неполадках:

```powershell
# Что реально передано службе
nssm get Ollama AppEnvironmentExtra

# Состояние NSSM (exit code, throttle, ротация)
nssm dump Ollama

# Проверить, что PATH применился
[Environment]::GetEnvironmentVariable('Path', 'Machine') -split ';' | Select-String -SimpleMatch 'Ollama'

# Проверить ACL на профиль и модели
icacls D:\AI\Ollama
icacls D:\AI\Models

# Что слушает порт 11434
Get-NetTCPConnection -LocalPort 11434 -State Listen | Select-Object OwningProcess, LocalAddress
```
